# 停止后录制动作节点的服务端权威新增与删除

这组增量为已停止且未配置分页循环的录制会话增加动作插入/删除 API，并让前端只在服务端返回完整权威快照后提交 UI 状态。动作 ID、pageId 和连续 order 均由服务端控制，popup opener 禁止删除；失败路径保留原 session、生成代码和删除确认框。真实 Cypress happy path、取消、503 与同 ID 重试均通过，`critical-flow` 也在停止前等待录制值进入检查器。当前存在一个会产生无效脚本的 popup 后代插入缺口，因此不应按现状合入。

Watch for: **[P1, confirmed, blocking]** 被排除 popup 的后代页面仍可插入 `included: true` 动作，生成代码会引用从未创建的 `pageN`；**[P2, confirmed, non-blocking]** 手工 fill 的隐私防线仅是提示，值仍会成为脚本文字面量；**[P2, confirmed, non-blocking]** API 所有权字段与焦点/互斥行为的自动化断言尚不完整。

**Verdict**: NEEDS_CHANGES

## High-level view

服务端通过动作白名单、内部 UUID、锚点 pageId 继承和一次性全数组重排维护结构所有权，并在 coordinator 层重复校验。stopped/no-loop 条件和 popup opener 删除锁都在权威层执行；但新插入动作无条件设为 included，绕过了已有的 popup 父级排除不变量。

前端把结构变更建模为单一 `mutating-actions` 操作，不做 optimistic splice。只有一致的 stopped snapshot 才会整体替换 session 并清生成物；失败不会关闭编辑/确认状态，也不会覆盖代码。

Cypress 通过真实服务端覆盖新增、编译、删除和代码恢复，并在取消与拦截 503 后验证节点、代码、确认框以及两次相同 action ID。`critical-flow` 在停止前等待检查器出现录制值，动作编辑 spec 则等待三个节点和权威 stop 响应。

手工 fill 值会跨 API 并被编译成文字面量，UI 仅提示密码和验证码改用人工步骤。如果“敏感输入不写入生成脚本”也覆盖手工结构编辑，这条边界尚未被策略或 E2E 强制。

### 被排除 popup 后代上的新增动作绕过页面所有权

**[P1, confirmed, blocking]** `insertAction` 从锚点继承 pageId 后把新动作固定为 `included: true`，没有调用已有的 `isPageExcludedByParent`（`apps/server/src/recording/recording-coordinator.ts:479-515`）。实时录入动作遇到被排除 opener 时会强制 `included = false`，单独重新启用后代动作也会被拒绝（`apps/server/src/recording/recording-coordinator.ts:434-440`, `apps/server/src/recording/recording-coordinator.ts:1136-1148`）。

```text
excluded opener on page0  --X-->  page1
                                  existing child: excluded
                                  inserted child: included=true

compiler: const page0 = page
          (opener skipped)
          await pace.click(page1.locator(...))  // page1 was never declared
```

非循环编译器只初始化 `page0`，只有 included popup opener 才生成 `const page1 = ...`，随后却会编译这个新动作（`apps/server/src/recording/action-script-compiler.ts:124-148`, `apps/server/src/recording/action-script-compiler.ts:362-375`）。应在父页面被排除时把插入动作存为 excluded，或返回 `parent_action_excluded`；测试需断言快照和代码都不存在悬空 page 变量。

### API 所有权正确收口，但关键字段回归用例缺失

route 与 coordinator 都要求动作对象具有精确字段集合，客户端放入 action 内的 `id`、`order` 或 `pageId` 会被拒绝。coordinator 内部生成 UUID、继承锚点 pageId，并在 opener/loop/stopped 检查后一次赋回重排序列（`apps/server/src/routes/recording-routes.ts:52-138`, `apps/server/src/recording/recording-coordinator.ts:143-221`, `apps/server/src/recording/recording-coordinator.ts:460-558`, `apps/server/src/recording/recording-coordinator.ts:983-1004`）。

**[P2, confirmed, non-blocking]** 测试只用 `id` 证明 extra-key 拒绝，pageId 继承也只覆盖 page0；没有分别锁定 `order`、`pageId` 拒绝和 popup 子页继承（`apps/server/src/routes/recording-routes.test.ts:162-178`, `apps/server/src/recording/recording-coordinator.test.ts:230-314`）。应参数化三个客户端所有权字段，并用 page1 锚点同时覆盖继承和父级排除。

### 权威快照保护失败恢复，焦点行为缺直接覆盖

`useRecording` 只在验证 stopped snapshot 与单动作/单删除结果一致后调用 `replaceSession` 和 `clearGeneratedArtifacts`；503 或 malformed envelope 只设置 error（`apps/website/src/composables/useRecording.ts:835-944`）。面板仅在插入成功后聚焦新节点，删除成功后按后继、前驱、Start 的顺序迁移；失败时 `deletingActionId` 保留确认框。loop 草稿、人工范围和另一结构编辑器受 `actionMutationActive` 阻断（`apps/website/src/components/tabs/RecordingPanel.vue:143-169`, `apps/website/src/components/tabs/RecordingPanel.vue:231-355`, `apps/website/src/components/tabs/RecordingPanel.vue:467-521`）。

**[P2, confirmed, non-blocking]** composable 测试覆盖 session/代码保留，Cypress 覆盖确认框保留，但没有断言插入后的新节点焦点、删除后的后继/前驱焦点或 editor/loop/manual 三方互斥（`apps/website/src/composables/useRecording.test.ts:157-260`, `e2e/features/recording/action-node-editing.p0.cy.ts:187-214`, `e2e/features/recording/action-node-editing.p0.cy.ts:236-290`）。现有 E2E 可直接检查 inspector 的 action ID/步骤，并在编辑器打开时断言其他编排入口 disabled。

### Cypress 等待权威停止状态并锁定单目标重试

动作编辑 journey 等待受管 Chrome 任务完成和三个 selector 节点出现，再读取 stop response 的 recording snapshot；后续锚点 ID 均来自该快照（`e2e/features/recording/action-node-editing.p0.cy.ts:69-85`）。新增等待真实 201 并检查精确 request body、服务端顺序和代码顺序；恢复路径验证取消零请求、503 后节点/代码/确认框不变，以及重试请求序列严格为 `[id, id]`、最终只移除该 ID（`e2e/features/recording/action-node-editing.p0.cy.ts:88-163`, `e2e/features/recording/action-node-editing.p0.cy.ts:219-290`）。

`critical-flow` 在 stop 前逐个聚焦两个公开 fill 节点并等待检查器显示 value，保证 action update 已到达前端，再由 stop response 提供最终 ID（`e2e/features/recording/critical-flow.p0.cy.ts:55-83`）。实际运行 `git diff --check`、`vp check`、`vp test` 和 `vp run e2e`：格式、lint、类型检查通过，44 个单测和 13 个 spec/28 个 Cypress 测试全部通过。

### 手工 fill 的敏感值边界仅由提示约束

**[P2, confirmed, non-blocking]** 新编辑器允许任意 fill value；提示要求密码/验证码改用人工步骤，但提交与 coordinator 不执行录制器已有的 sensitive-control 判定，编译器会直接序列化该值（`apps/website/src/components/recording/RecordingNodeInspector.vue:450-480`, `apps/server/src/recording/recording-coordinator.ts:169-178`, `apps/server/src/recording/action-script-compiler.ts:61-66`, `apps/server/src/recording/action-script-compiler.ts:136-138`）。若这是明确的脚本创作边界，应收窄“敏感输入不记录”的文档保证并测试 warning/人工替代路径；若保证覆盖整个录制工作台，则必须拒绝明显敏感 selector/value。
