# 隔离 Chromium/noVNC 录制窗口与 Vue Flow 工作台重构

本轮把录制 UI 移入独立工作台，以 noVNC 经 Fastify WebSocket↔VNC bridge 操作隔离 Chromium，并用 Vue Flow 表达动作、人工 checkpoint 与分页循环。当前不能按方案 A 交付：持久 Chromium profile 和可调用的 JPEG 通道仍允许落盘/截图，工作台离开或启动失败也可能遗留服务端录制。bridge 的压力与握手恢复不完整，现有 E2E 又使用与 Chromium 脱节的伪 RFB 服务，无法证明真实容器边界。

Watch for: **[P0，confirmed]** 持久 profile 与 JPEG preview 违反“敏感内容不得落盘/截图”；**[P1，confirmed]** start/unmount/route-leave 竞态可遗留录制 lease；**[P1，confirmed]** bridge 没有真实背压且 RFB 握手可永久卡住；**[P1，confirmed]** 22/22 Cypress 未经过实际 x11vnc↔Chromium 链路。

**Verdict**: NEEDS_CHANGES

## High-level view

**[P0，confirmed]** `/home/browser/profile` 被挂到 `crawlcbg-browser-profile` named volume，并在 `browser:down` 后保留；与此同时，已经不用 JPEG 的前端仍对应一个新增的服务端 screenshot route。两条路径分别破坏方案 A 的“不落盘”和“不截图”边界。

**[P1，confirmed]** 工作台销毁只发出不等待结果的 keepalive stop；若销毁发生在 start 响应落入 `session` 前，recordingId 也不会被回收。UI 可以离开，而 recorder、live-view grant 和独占 browser-activity lease 继续存在。

**[P1，confirmed]** bridge 忽略 TCP `write()` 的背压信号，输出积压时也只会超过阈值后断线；TCP 建连后还立即撤销唯一 timeout。慢客户端会反复重连，半开 RFB 服务则可让界面永久停在“正在连接”。

**[P1，confirmed]** 独立路由只携带可变 tab index，再以重新读取到的 URL 发起 start。索引漂移会把原来的 expected-URL 保护替换成另一个页面的 URL。

**[P1/P2，confirmed]** 自动化把伪 RFB、真实 Chrome 和隐私扫描拆成互不相连的路径；Vue Flow 的 nested-parent 断言也只检查组件自己写入的属性。真实镜像、按键释放、背压、profile/日志泄漏、父子移动和 graph→compiler 一致性均可在全绿测试下失效。

<details><summary>Details</summary>

### Chromium profile 跨录制持久化

**[P0，confirmed]** `infra/browser-session/compose.yaml::chromium.volumes` 把 `/home/browser/profile` 映射到具名卷，`infra/browser-session/README.md` 明确说明 `browser:down` 保留它；`Dockerfile`/`entrypoint.sh` 让 Chromium 直接使用该目录。禁用密码管理和 autofill 不能阻止页面存储、cookies、会话或恢复状态写入 profile。应把 profile/cache 改为每个隔离会话独享的 tmpfs/匿名易失存储并在 stop/shutdown 销毁；若必须保留登录态，应作为方案 A 之外的显式模式。

### RFB 之外仍保留 JPEG 截图旁路

**[P0，confirmed]** `BrowserRecorder.capturePagePreview` 调用 `screenshot()`，`RecordingCoordinator.capturePagePreview` 转发，`registerRecordingRoutes` 暴露 `GET /api/recordings/:id/pages/:pageId/preview`。`RecordingBrowserWindow.vue` 已不使用它，Cypress 也只断言请求数为零；但 route/unit tests 又固定了该能力。`previewPrivacyLocked` 仅在 recorder 看到 `manualStep` 后生效，挡不住预填内容、分类遗漏或此前画面。应删除 screenshot handle、coordinator 方法、route 与对应测试，而不是依赖事后 lock。

### 工作台销毁无法保证 coordinator stop

**[P1，confirmed]** `RecordingWorkspaceView.onBeforeRouteLeave` 在确认后立即放行，提示却承诺“离开会停止录制”。实际停止来自 `useRecording.onScopeDispose` 的 `bestEffortStop`：它 fire-and-forget 一个 keepalive POST，吞掉失败且不阻塞路由；请求丢失后 RFB 已断开，但 recording 与 lease 仍继续。

`useRecording.startRecording` 还有无句柄窗口：组件在响应落入状态前销毁会直接丢弃 payload；`normalizeRecording` 成功而 `normalizeLiveView` 失败时也只进入 catch，不 stop 已取得的 recordingId。

```text
POST /recordings commits recorder + grant + lease
                 |
                 +--> disposed / liveView envelope rejected
                                      |
                                      +--> session null; no stop
```

一旦响应含 recordingId，descriptor 校验、scope dispose 或后续初始化失败都必须显式 stop；route guard 应等待 stop 成功再导航。更稳妥的是以客户端 owner/request id 让服务端在请求中止或 owner 失联时幂等回收。Cypress 应覆盖“starting 时离开”和“录制中确认离开”，并断言随后可立即开始新录制/执行。

### tab index 路由可重新绑定到错误页面

**[P1，confirmed]** `TabsView.openRecordingWorkspace` 只传 `tab.index`；`RecordingWorkspaceView.loadTarget` 随后接受当前位于该 index 的任意页面，并用它的新 URL 调用 start。前序 tab 在这段时间关闭/重排时，coordinator 校验的是替代页面而非点击时目标；同 route 的 `tabIndex` 参数变化也没有 watcher。应传并校验稳定 target id；暂时没有 id 时至少传点击时 expected URL、发现不一致即拒绝 auto-start，并 watch route params。补 Cypress 在 workspace 拉取 tabs 前制造索引漂移。

### bridge 以断线代替双向背压

**[P1，confirmed]** `RecordingLiveViewManager.bridge` 在 client→TCP 方向忽略 `upstream.write(input) === false`，批量 flush `pendingInputs` 也不等 `drain`；TCP→WebSocket 方向持续读取，直到 `client.bufferedAmount` 超过 4 MiB 才关闭。暂时慢客户端因此丢失整条 RFB 会话和未完成输入；`x11vnc -clear_keys` 只能降低断开后的粘键风险。

应采用高/低水位：TCP write 返回 false 时暂停 WebSocket 输入并等 `drain`；WebSocket 积压时暂停 upstream，在 send callbacks 降到低水位后恢复，硬上限仍 fail closed。fake socket 测试需模拟 `write(false)`、变化的 `writableLength`、`drain` 和慢 send callback，验证顺序、上限和恢复。

### TCP connect 后没有 RFB 握手 watchdog

**[P1，confirmed]** manager 的 `connectTimeoutMs` 只覆盖 TCP 建连，`upstream.once("connect")` 随即 `setTimeout(0)`。端口若接受连接但不发 RFB banner，WebSocket 会保持打开；noVNC 1.7.0 只有 disconnect timeout，`RecordingBrowserWindow.connectLiveView` 也没有 connecting watchdog，所以 overlay 不会进入 `scheduleReconnect`。token renewal fetch 同样没有 timeout。

应给每个 `connectionGeneration` 设置端到端 deadline，在 noVNC `connect` 时清除；超时后断开、续发 token 并进入有上限重连，renew fetch 使用独立 timeout signal。测试需覆盖“TCP accept 后静默”和“token endpoint 不返回”，并验证 retry/unmount 零残留。

### RFB/隐私 E2E 验证的是替身而不是真实边界

**[P1，confirmed]** `e2e/support/p0-harness.ts::RfbFixtureServer` 与 managed Chrome 完全脱节，只返回 server init/空 framebuffer update。`window-stream.p0.cy.ts` 的普通 `r` 键进入 fixture，隐私 canary 却由 CDP `Input.insertText` 写入 Chrome；测试没有覆盖敏感键经 RFB、真实画面、held-key 断线释放或 x11vnc flags。

`startChrome` 把 profile 放在 `caseRoot/chrome-profile`，`privacySnapshot` 却只扫描 `runtimeDir`，也不扫描 captured process output；canary 写进 profile/日志仍会得到空 `canaryHits`。应保留 fixture 作为 protocol smoke，另加真实 Docker Cypress journey：从 noVNC 输入 canary、确认真实画面、按住键强制断链并验证释放，再扫描整个 case root、容器存储和进程日志。Docker 未运行意味着该最高风险路径仍未验证，不能由 22/22 代替。

### Vue Flow nested parent 与 compiler 一致性没有端到端证明

**[P2，confirmed]** `pagination-loop.cy.ts` 只检查组件自己写入的 `data-parent-node="pagination-loop"`；Vue Flow 即使忽略 `parentNode`/`extent`，测试也会通过。该 journey 创建循环后也未生成代码。应拖动 loop parent 并断言 children 随父节点移动且受其约束，再从同一 session 生成脚本，确认 body/Next 嵌套与 graph 一致，解散后确认 compiler 恢复线性顺序。

### live-view 与 coordinator 回滚测试没有故障注入

**[P2，confirmed]** `recording-coordinator.test.ts` 未注入 `RecordingLiveViewGateway`，所以没有断言 `open/revoke/shutdown`、recorderFactory 失败后的 grant 回滚、recorder.stop 失败时的 revoke/lease release 或并发 stop/shutdown。`recording-live-view.test.ts` 也不触发 timeout、pressure 和 socket error。应增加可观测 fake gateway 和分阶段故障注入，断言 grant、bridge、recorder、record map 与 lease 最终均被回收且 stop/shutdown 幂等。
