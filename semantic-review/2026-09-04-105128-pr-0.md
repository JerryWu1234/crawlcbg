# 用独立 iframe URL 预览替换录制实时窗口

这组变更把录制工作台从 Docker/noVNC/RFB 实时窗口收缩为独立 URL iframe，同时保留 Vue Flow、stable CDP `targetId`、普通录制 SSE、orphan grace 和动作录制/编译。生产代码、直接依赖、配置、基础设施与协议套件中未发现旧传输残留，JPEG preview API 也已移除。真实栈 Cypress 覆盖了录制、停止、人工步骤、编译、保存、目标替换和导航清理；静态检查、39 个单测和 26 个 Cypress 测试全部通过。没有阻塞问题，剩余项均为 P2 hardening/coverage follow-up。

Watch for: **[P2, confirmed, non-blocking]** iframe sandbox 同时开放 scripts、same-origin、forms、modals 和逃逸 sandbox 的 popup，权限超过“最小预览”；**[P2, confirmed, non-blocking]** start normalizer 接受任意 ID-bearing payload，令 malformed-response 补偿分支不可达；**[P2, confirmed, non-blocking]** iframe Cypress 只验证 URL/响应头/链接属性，没有证明实际渲染、fallback 打开或 non-capture；**[P2, confirmed, non-blocking]** orphan grace 没有经过真实 SSE socket 断链的端到端验证。

**Verdict**: APPROVED

## High-level view

录制预览现在由客户端根据 `RecordedPage.url` 发起独立导航。URL 仅允许 HTTP/HTTPS，新标签链接带 `noopener noreferrer`，iframe 不发送 referrer，固定 warning 说明 framing、会话和 non-capture 边界；sandbox 的授权范围仍大于只读预览所需。

目标选择改为 CDP identity 优先：history handoff、工作台重验证、start body 和 coordinator 最终查找都携带 `targetId + URL`，同 URL replacement 不会被误录。服务端成功 envelope 固定为 `{ recording }`，客户端随后连接普通 EventSource，但客户端的宽松 normalizer 没有真正执行 malformed-envelope cleanup。

start 后立即进入 orphan grace，SSE subscribe 认领会话，最后 unsubscribe 重新启动 grace；stop 即使 cleanup 报错也会标记 stopped 并释放 lease。导航 journey 验证了延迟 start/stop，coordinator 单测验证了 grace，但真实 socket 断开到自动回收仍缺集成证据。

Vue Flow、动作录制、人工步骤、分页循环和编译/保存继续走 RecordingSession/SSE/HTTP 数据面，不依赖 iframe。真实栈 journey 覆盖这些能力；iframe failure journey 目前证明的是 DOM contract，而不是浏览器实际呈现与恢复操作。

<details><summary>Details</summary>

### iframe sandbox 超出独立预览所需权限

`RecordingPagePreview` 只把可解析的 `http:`/`https:` URL 送入 iframe 和 fallback；fallback 使用 `_blank`、`noopener noreferrer`，iframe 使用 `no-referrer`，固定 footer 说明 framing、独立会话和 non-capture 边界（`apps/website/src/components/recording/RecordingPagePreview.vue:18-26`, `apps/website/src/components/recording/RecordingPagePreview.vue:42-65`, `apps/website/src/components/recording/RecordingPagePreview.vue:93-95`）。

**[P2, confirmed, non-blocking]** iframe 同时授予 `allow-forms allow-modals allow-popups allow-popups-to-escape-sandbox allow-same-origin allow-scripts`。同源目标在 scripts + same-origin 下可以访问 parent DOM，目标还可在用户激活后创建不继承 sandbox 的 popup；modal/form 权限也不是最小 URL 预览的必要条件（`apps/website/src/components/recording/RecordingPagePreview.vue:59-65`）。应删除非必要 token；若动态站点必须保留 scripts/same-origin，应把 preview 放到独立 origin，并显式定义 operator-browser cookie/storage 与 popup 信任边界。

### start envelope 的补偿分支不会处理 ID-bearing malformed payload

服务端成功响应固定为 `{ recording: RecordingSession }`，且 route test 断言不再出现 `liveView`（`apps/server/src/routes/recording-routes.ts:57-75`, `apps/server/src/routes/recording-routes.test.ts:73-87`）。

**[P2, confirmed, non-blocking]** `recordingIdFromPayload` 取得 ID 后试图在 normalization 失败时补偿 stop，但 start 调用 `normalizeRecording(payload, target.url, true)`；`allowIdOnly=true` 会把任何带字符串 `id` 的对象合成为 session。因此 `returnedRecordingId` 非空时 `recording` 不会为 null，补偿分支不可达，空字符串 ID 也会被接受（`apps/website/src/composables/useRecording.ts:295-331`, `apps/website/src/composables/useRecording.ts:738-750`）。应严格验证声明的 envelope 并对可恢复 ID stop，或删除死分支并将 id-only 作为正式契约测试。

### SSE ownership 闭合，但真实断链回收未被 journey 验证

start 安排 orphan timer，subscribe 清除 timer，最后 unsubscribe 重新安排；stop 清 timer，并在 recorder cleanup 后标记 stopped、释放 lease。SSE route 在 raw response `close` 上 unsubscribe 并清 heartbeat（`apps/server/src/recording/recording-coordinator.ts:240-296`, `apps/server/src/recording/recording-coordinator.ts:701-755`, `apps/server/src/recording/recording-coordinator.ts:1024-1050`, `apps/server/src/routes/recording-routes.ts:89-129`）。

**[P2, confirmed, non-blocking]** grace 单测直接调用 `subscription.unsubscribe()`，两个 lifecycle Cypress journey 都成功发出显式 `/stop`（`apps/server/src/recording/recording-coordinator.test.ts:538-590`, `e2e/features/recording/lifecycle-navigation.p0.cy.ts:17-74`）。它们无法发现 Fastify raw-close、浏览器 EventSource 与 coordinator 之间的集成断裂。建议在 harness 中缩短 `RECORDING_ORPHAN_GRACE_MS`，模拟 hard reload/network loss 并阻止 best-effort stop，再以新 recording/execution 成功证明 lease 已回收。

### iframe Cypress 没有执行真正的呈现、fallback 或 non-capture 行为

**[P2, confirmed, non-blocking]** happy journey 验证 chip、URL、iframe `src` 和 fallback `href`；blocked journey 用独立 `cy.request` 检查 `X-Frame-Options: DENY`/`frame-ancestors 'none'`，再检查 warning 与链接属性。两者都没有读取 frame 内 marker、等待 postMessage、点击 `_blank` fallback，或在 iframe 内交互后确认 RecordingSession action count 不变（`e2e/features/recording/iframe-window.p0.cy.ts:32-58`, `e2e/features/recording/iframe-window.p0.cy.ts:61-97`）。增加可观察 loaded marker、真实 fallback 导航和 non-capture 断言，才能覆盖该替代方案最高风险的用户可见失败。
