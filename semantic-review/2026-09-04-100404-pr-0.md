# Recording workspace with bounded ownership and tokenized noVNC transport

The recording workspace now resolves the selected Chrome page by stable CDP target identity, serves the full browser window through a recording-bound noVNC capability, and bounds abandoned recordings with an initial-unclaimed/SSE-disconnect grace period. The four findings from the previous pass are addressed in production paths and backed by focused unit or Cypress coverage. Explicit stop cleanup releases browser ownership even when recorder or live-view teardown reports errors, and route navigation waits for committed start/stop work rather than abandoning it mid-transition. No P0 or P1 blocker remains in the reviewed diff.

Watch for: **[P2, confirmed]** the deterministic RFB fixture still does not validate the real Docker/Xvfb/Openbox/x11vnc/Chromium stack or tmpfs recreation; this is non-blocking because the README labels the boundary accurately and carries it as a Linux/Docker CI follow-up rather than claiming it passed.

**Verdict**: APPROVED

## High-level view

Recording ownership is now server-authoritative. `RecordingCoordinator.start` arms a grace timer before returning an active session, the first SSE subscriber claims it, and the final unsubscribe rearms it; explicit stop marks the session stopped and releases the exclusive browser lease even if resource cleanup rejects.

The clicked tab’s `targetId` is emitted by `/api/tabs`, stored in router history state, revalidated by the workspace, sent in the start envelope, and resolved again by the coordinator. Index remains display/order metadata, while CDP identity plus exact URL prevents index churn or a same-URL replacement from redirecting recording.

The RFB path uses short-lived recording-bound capabilities outside URLs, trusted-origin renewal and WebSocket handshakes, loopback-only VNC, bounded queues, and connection deadlines. Stop/revoke closes the bridge, while generation-scoped noVNC retries cannot revive stale connections.

Navigation guards await an in-flight committed start and then the idempotent stop. Hard unload cannot await HTTP cleanup, but loss of the SSE claim enters the same server grace path as a lost start response.

Privacy coverage now claims only the UI and `runtimeDir`, matching the canary implementation, and explicitly excludes the managed-Chrome profile, process buffers, Docker tmpfs lifetime, and Linux window-stack compatibility. Pagination Cypress now measures rendered parent/child motion and child bounds in addition to compiler creation and dissolution.

### Initial-unclaimed and disconnected SSE ownership bound abandoned recordings

`RecordingCoordinator.start` calls `scheduleOrphanCleanup` before returning (`apps/server/src/recording/recording-coordinator.ts:226-279`). A subscription clears the timer and unsubscribe rearms it (`apps/server/src/recording/recording-coordinator.ts:312-324`, `apps/server/src/recording/recording-coordinator.ts:1098-1120`); the SSE route maps `reply.raw` close to unsubscribe and emits heartbeats so dead transports are observed (`apps/server/src/routes/recording-routes.ts:153-193`).

```text
start committed
      |
      +-- no SSE claim -------------------- grace --------------------> stop
      |
      +-- SSE subscribed --> timer cleared --> disconnect --> grace --> stop
```

`stop` marks the session stopped and releases the browser lease in `finally`, then reports any live-view or recorder cleanup failure (`apps/server/src/recording/recording-coordinator.ts:743-793`). Startup rollback also releases the lease when live-view revocation fails (`apps/server/src/recording/recording-coordinator.ts:281-307`). Tests cover unclaimed expiry, subscriber disconnect expiry, startup rollback failure, and teardown cleanup failure (`apps/server/src/recording/recording-coordinator.test.ts:482-647`). A client that never receives the start envelope therefore needs no response-derived ID to be reclaimed, and failed browser keepalive delivery is no longer the only teardown mechanism.

### CDP target identity replaces index/URL as the recording selector

`/api/tabs` returns a required stable `targetId` (`apps/server/src/routes/tab-routes.ts:23-39`). The click handoff stores ID and URL in history state (`apps/website/src/views/TabsView.vue:224-231`); the workspace refreshes tabs and requires that identity/URL pair before mounting (`apps/website/src/views/RecordingWorkspaceView.vue:36-88`). The start body carries the ID (`apps/website/src/composables/useRecording.ts:728-758`), and the coordinator finds the visible page by ID, then rechecks closure and exact URL immediately before recorder creation (`apps/server/src/recording/recording-coordinator.ts:184-279`).

The fixed `rootPage` object prevents later page-array reordering from changing the recorder target. Both coordinator coverage and Cypress replace only the ID while preserving the URL and verify fail-closed behavior; Cypress also verifies that no start request is sent (`apps/server/src/recording/recording-coordinator.test.ts:618-647`, `e2e/features/recording/target-selection.cy.ts:15-48`).

### noVNC capability and bridge lifecycle fail closed

The live-view manager accepts only loopback VNC hosts, hashes production tokens, binds each digest to one recording, and enforces expiry before bridge creation (`apps/server/src/recording/recording-live-view.ts:43-178`). Tokens use a WebSocket subprotocol rather than a query string; renewal and upgrade require a trusted localhost/loopback origin, and capability responses are non-cacheable (`apps/server/src/routes/recording-routes.ts:74-142`). Fastify itself listens on loopback, disables WebSocket compression, and caps payloads (`apps/server/src/app.ts:32-48`).

Client input pauses under TCP pressure and has a hard pending-byte cap. TCP output pauses/resumes at separate watermarks and closes before the WebSocket buffer exceeds its hard cap; connect and RFB-handshake silence also have deadlines (`apps/server/src/recording/recording-live-view.ts:180-359`). Revocation invalidates the token, closes the bridge, destroys upstream TCP, and removes the grant (`apps/server/src/recording/recording-live-view.ts:361-377`).

The noVNC component scopes renewals, watchdogs, callbacks, and retries to a connection generation, so stop, prop change, or unmount invalidates stale async work (`apps/website/src/components/recording/RecordingBrowserWindow.vue:80-245`). Unit coverage exercises token binding/expiry, binary forwarding, pressure limits, revocation, and handshake timeout; the P0 fixture covers the production client/bridge, cross-recording rejection, input, renewal, disconnect, and silent-upstream recovery (`apps/server/src/recording/recording-live-view.test.ts:108-269`, `e2e/features/recording/window-stream.p0.cy.ts:50-179`).

### Route leave waits for committed start and stop work

`stopForNavigation` awaits the retained start promise, then the shared stop promise, and succeeds only after stopped state is visible (`apps/website/src/components/tabs/RecordingPanel.vue:327-362`). Route leave and target-changing updates use that contract (`apps/website/src/views/RecordingWorkspaceView.vue:143-164`). Scope disposal leaves committed start/stop requests alive, closes SSE, aborts other work, and sends a best-effort keepalive stop when it has an active ID (`apps/website/src/composables/useRecording.ts:1316-1356`).

The real-stack journeys delay start and stop responses and keep the route in the workspace until server cleanup completes (`e2e/features/recording/lifecycle-navigation.p0.cy.ts:17-82`). Hard unload remains non-awaitable, but initial-unclaimed and SSE-disconnect cleanup cover that recovery path server-side.

### Privacy evidence and Docker boundary match their actual scope

The canary recursively scans only `runtimeDir`, while Cypress separately checks the workspace UI (`e2e/support/p0-harness.ts:1426-1448`, `e2e/features/recording/window-stream.p0.cy.ts:157-164`). The README now names that exact scope and excludes the managed Chrome profile, process memory, and every child-process buffer (`e2e/README.md:52-55`).

**[P2, confirmed]** The protocol fixture cannot prove Linux package compatibility, browser-chrome pixels, or Docker tmpfs lifetime; the README specifies a Linux/Docker smoke follow-up instead. Compose declares bounded tmpfs profile/cache mounts and loopback CDP/VNC publishing, while the infrastructure README keeps host swap and hibernation outside the guarantee (`infra/browser-session/compose.yaml:1-20`, `infra/browser-session/README.md:13-29`). Docker was unavailable, so those runtime properties are not represented as executed validation. This documented, non-blocking follow-up is the only remaining coverage gap.

### Vue Flow containment is exercised through rendered motion

Loop actions use `parentNode: "pagination-loop"`, `extent: "parent"`, and parent-aware saved positions (`apps/website/src/components/recording/RecordingFlowGraph.vue:96-166`, `apps/website/src/components/recording/RecordingFlowGraph.vue:232-276`). Cypress verifies the parent moves more than 20 pixels, each child follows the same delta within three pixels, and an out-of-bounds child drag leaves all four child edges inside the current parent rectangle (`e2e/features/recording/pagination-loop.cy.ts:125-248`).
