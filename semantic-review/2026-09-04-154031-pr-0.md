# Popup 子页新增动作继承父级排除状态

本轮修复让停止录制后的手工插入复用 popup 祖先排除判定，避免在未执行 opener 时生成依赖子页面的动作。新增动作仍从锚点继承 pageId，但初始 included 由整条 opener 祖先链决定。回归用例复现 excluded opener、page1 child、stop、child 后插入及脚本生成的完整链路。按本轮只看 blocker/P1 的门槛，结论为 `Verdict: PASS`。

## High-level view

`insertAction` 从锚点取得服务端权威 pageId，再用 `isPageExcludedByParent` 初始化 included；直接或嵌套 popup 的任一祖先被排除时，新节点都会保持 excluded。严格 normalize 的 draft 无法覆盖 pageId/included。

编译器会丢弃 `included === false` 的动作，因此被排除 opener 不声明 `page1` 时，新增 child 也不会生成 selector 或引用该变量。测试同时断言权威插入结果和真实 compiler 输出；定向 coordinator 测试 14/14 通过，补丁 `git diff --check` 通过。

插入动作现在以 `included: !this.isPageExcludedByParent(record, pageId)` 入库（`apps/server/src/recording/recording-coordinator.ts:511`）。helper 沿 `RecordedPage.openerPageId` 检查每层 `opensPageId` 对应动作（`apps/server/src/recording/recording-coordinator.ts:1172-1182`），因此不仅覆盖直接 page1，也覆盖更深的 popup 后代。
